## Problem

When a test_suite or implementation imports from a module that is NOT the direct `interface_ref` (e.g., a shared model module referenced by multiple interface specs), the gate's subprocess-based pytest/mypy collection fails with `ModuleNotFoundError`.

**GR006a instance:**
- `wi_fr02_tls_scan` and `wi_fr03_file_upload` both reference `certificate_model` as a dependency
- Test suites generated by test_author import `from certificate_model import Certificate`
- `_run_pytest_collect()` copies only the direct `interface.pyi` → `interface.py`
- `certificate_model.pyi` is not copied → pytest collect fails → gate_escalation

**Affected gate functions:**
- `_run_pytest_collect()` — `TEMPFILE_PREFIX_COLLECT`
- `_run_pytest()` — `TEMPFILE_PREFIX_PYTEST`
- `_run_mypy()` — `TEMPFILE_PREFIX_MYPY`

## Root cause

The scheduler propagates `interface_ref` (the direct parent interface_spec) into downstream work-items, but it does NOT propagate transitive dependencies. Even if it did, the gate functions only resolve and copy a single `interface.pyi` file.

## Impact

- Any multi-module workload (where interface specs depend on shared types/modules) will hit this
- GR006a implementation lock rate dropped from expected ~70% to 33% because 2 of 3 test_suites failed collect
- Phase 3 cannot start until resolved

## Proposed fix

Two complementary changes:

### 1. Scheduler: propagate dependency chain

Add `dependency_refs: list[str]` to work-item `custom_fields` (or as typed links). When creating a test_suite or implementation, scan the source interface_spec's spec text for `interface_ref` dependencies and copy them into the downstream item's `custom_fields["dependency_refs"]`.

### 2. Gate: copy all dependencies into temp directory

Update `_run_pytest_collect`, `_run_pytest`, and `_run_mypy` to:
1. Read `dependency_refs` from work-item `custom_fields`
2. Resolve each ref to its artifact_path via `_resolve_ref_artifact()`
3. Copy each `.pyi` → `.py` into the temp directory alongside `interface.py`

**Estimation:** ~40 lines in scheduler.py + ~30 lines in gate.py + 4 tests. Half-day of work.

## Risk

- If the fix is complex (e.g., circular dependency handling), it may require a more general module graph approach. But for the cert-watch workload, the dependency graph is a simple DAG (certificate_model → fr02/fr03).
- Alternative: restrict test_author prompt to never import from cross-module dependencies. This is a prompt-level fix but may reduce test expressiveness.

## Decision needed

Principal should choose:
- **Option A (structural fix):** Implement scheduler dependency propagation + gate temp directory copying. Unblocks multi-module workloads permanently.
- **Option B (prompt fix):** Update test_author.md to instruct "only import from the direct interface module; do not import shared models". Simpler but constrains test design.
