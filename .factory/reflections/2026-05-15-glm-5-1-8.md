## On the project

The codebase continues to be well-structured for incremental work. The constant convention (everything in `constants.py`), config centralization (`FactoryConfig`), and clear module boundaries make adding new features nearly mechanical. The biggest growing concern is the number of "implemented but not exercised" modules — state_reporter, checkpoint, bundler, catalog, ops — all land without golden-run validation. This is a deliberate Phase 5 tradeoff (build the skeleton, validate later), but it means the next golden run is load-bearing for a lot of new code.

The router refactor (RFC-005) feels like the right move at the right time. The dispatch table pattern was already cleaner than v1's if/elif chain, but the handler pipeline makes it genuinely extensible — the `CustomHandler` test shows that a new failure mode just needs a handler class and an insertion into `_HANDLERS`. The escalation and routing-hint logic being separate handlers rather than nested ifs in `route()` is a real clarity win.

## On the work done

**Confident in:** The three gap fixes are all straightforward and correct. The ensure_upstream_revision wiring is the most interesting one — calling a scheduler function from gate_process breaks the "gate_process only does transitions" pattern, but the alternative (scheduler polling via substrate events) would be heavier and slower. The direct call is the right Phase 5 choice. The bundler fix using `find_resumable_artifact` properly delegates to workspace.py instead of reimplementing directory walking. The --archetype flag is minimal and backward-compatible.

**Less confident in:** The state reporter's `_collect_recent_failures` method reads events with `transition=TRANSITION_GATE_FAIL`, but substrate's `read_events` API may not support transition filtering in all backends. The method has a try/except that returns `[]` on failure, which hides issues but avoids crashes. The checkpoint module's `can_resume_from_checkpoint` only checks config hash and project name — it doesn't check if the work items in the checkpoint still exist in substrate. A destructive `--reset` between checkpoint and resume would silently skip items. The config hash is a SHA-256 truncated to 16 hex chars — collision risk is negligible but the truncation is undocumented.

## On what remains

2. **Integration of checkpoint into the pipeline lifecycle.** `write_checkpoint` exists but nothing calls it automatically. The scheduler should write checkpoints after stage handoffs complete, but this needs a design decision on when exactly (post-all-locked? post-each-stage?).
3. **State reporter integration with ops watchdog.** RFC-017's watchdog and RFC-018's `--watch` mode overlap. Could fold the stall detector into the state reporter's periodic output.
4. **Remaining Phase 3–5 RFCs.** 15 still open. Of those, RFC-007 (mutation testing), RFC-014 (staff engineer summarizer), and RFC-001 (prompt conflict detection) are the highest-value next targets.

## Gaps to flag

- **`ensure_upstream_revision` call site violates gate_process boundary.** gate_process.py:351 now creates work items (via scheduler), not just transitions. This is architecturally impure but pragmatically correct. If gate_process grows more work-item-creation calls, extract a mediator. `src/factory/gate_process.py:351`
- **State reporter `_collect_recent_failures` reads events with transition filter.** Substrate's `read_events` transition parameter may not be supported in InMemorySubstrate, making the method silently return empty in tests. `src/factory/state_reporter.py:148`
- **Checkpoint `can_resume_from_checkpoint` doesn't verify work items still exist.** A `--reset` between checkpoint and resume would produce a false-positive "OK" result. `src/factory/checkpoint.py:171`
- **`ArtifactManifest` lacks `work_item_type` field.** Bundler, checkpoint, and state reporter all need this info but can't get it from the manifest. They either infer from filenames or do without. Adding it to `ArtifactManifest` and populating it at write time would be a clean fix. `src/factory/workspace.py:17`
- **Router `_HANDLERS` list is mutable module-level state.** The `test_custom_handler_extends_pipeline` test temporarily mutates it and restores. This works but is fragile under concurrent test execution. Consider making `_HANDLERS` a tuple with a `build_pipeline()` factory. `src/factory/router.py:195`
