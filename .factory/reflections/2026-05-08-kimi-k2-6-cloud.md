## Gaps to flag

- **`runner.py:_create_channel` error message for unknown channels** raises a generic `NotImplementedError` that doesn't tell the user which channel names were found. Easy DX improvement.
- **`OpenCodeChannel.__init__` mutates `self._family` lazily during `invoke()`** based on the role config's model. This is fine for single-channel usage but could be surprising if the same channel instance were reused across roles in multi-channel mode. Not a bug today.
- **No integration test for actual opencode CLI invocation.** The unit tests mock subprocess; a real `opencode run` integration test would require the binary in PATH and is probably not worth the CI flakiness at this stage.
- **`tests/test_pipeline_integration.py` `_BadImplIntegrationChannel` uses bare `except` to trigger lint failures.** This is a brittle coupling to ruff's rule set. If ruff ever auto-fixes E722 (unlikely, but possible), this test silently passes through the gate. Consider a more durable failure mode (e.g., deliberate mypy violation) in the future.
- **`output_extraction.py` is imported by both channel adapters but isn't independently tested.** It has indirect coverage through `test_claude_code_channel.py` and `test_opencode_channel.py`; if extracted functions change, failures show up in channel tests rather than a dedicated unit test.
