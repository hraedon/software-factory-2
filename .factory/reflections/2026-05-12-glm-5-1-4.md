# Session Reflection — 2026-05-12

**Work summary:** Implemented RFC-015 (dependency import manifest + gate-level import validation), BC-128 (cross-attempt defect taxonomy), BC-126 (work-item granularity measurement), and BC-127 (spec linting). 66 new tests, 0 lint errors. Filed BC-129 for 10 pre-existing substrate test failures.

---

## On the project

This codebase is unusually well-documented for its size. The breadcrumb system is the best part — every defect has context, v1 precedent, and scope boundaries. The RFC-015 review from Opus was the most detailed design review I've seen in a codebase: 10 sections with specific line-number directives. It made implementation straightforward because ambiguity was eliminated before I started.

The weakest part is test isolation from substrate. 10 tests fail because substrate changed its actor_metadata API from objects to dicts, and nobody noticed because they're not in the CI gate. The factory's integration tests are tightly coupled to substrate's internal representation — they reach into `_events.py` internals rather than going through a stable contract.

The prompt rendering pipeline (context.py → render_prompt → channel) is clean. Adding the export_map and manifest was surgical. The inner gate cascade in runner.py is getting long but the pattern is clear enough.

## On the work done

**RFC-015** was the biggest piece. The `extract_exports` function originally tried to reuse `structural_signature` output but that missed bare `ast.Assign` type aliases (e.g. `CertFormat = str | bytes`). I rewrote it to do its own AST walk at module level, which is simpler and more correct. The TYPE_CHECKING block detection needed two iterations — first version only set a counter but didn't skip imports inside the block, second version correctly collects node IDs from the `if TYPE_CHECKING:` subtree. The `export_map is None` vs `not export_map` bug caught by the relative-import test was a real edge case — empty dict vs None matters.

**BC-128** was the most architecturally interesting. The corpus builder reads from substrate (not files), which means it can only extract from live databases. Historical GRs that no longer have a running substrate can't be backfilled. This is a real gap — the BC assumes `runs/GR-*/` telemetry directories but those don't exist. The tool works for the forward-looking case, which is the important one.

**BC-126** was straightforward measurement plumbing. The `_count_ac_bullets` parser is fragile (it counts `- ` prefixed lines in the AC section) but the BC explicitly says "cheap, mechanical signals."

**BC-127** was clean. Check #4 (measurable verbs) was already deferred by Opus's update, which was the right call. The symbol reference check (#5) reuses the export_map concept from RFC-015 but without coupling to it — spec_lint.py doesn't import from gate.py or pre_gate.py.

I'm confident in all four implementations. The one thing I'd want eyes on is the `validate_artifact_imports` function in pre_gate.py — the TYPE_CHECKING detection walks `ast.walk` on the If node to collect child IDs, which works but is a bit unusual.
