**Work summary:** Resolved BC-084 (module name derivation from spec titles was fragile) by adding a `CUSTOM_FIELD_MODULE_NAME` custom field that `populate_work_items.py` sets from the fixture label. `dep_resolution.py` now reads this field first, falling back to the regex only when absent. ## On the project

The pipeline is genuinely close to working end-to-end on a realistic multi-module DAG. GR-014 showed 91% lock rate with only 2 failures — both model quality issues, not pipeline bugs. The architecture is holding up well under real workloads. The `module_name` custom field is a clean single-source-of-truth fix that eliminates an entire class of ImportError failures.

The golden run process is becoming routine. The `setsid` trick for long-running processes is necessary because the bash tool's 2-minute timeout kills foreground processes — AGENTS.md should document this.

## On the work done

The BC-084 fix was clean and minimal:
- Added `CUSTOM_FIELD_MODULE_NAME` to constants.py
- `populate_work_items.py` strips `wi_` prefix from label and stores as custom field
- `resolve_dep_artifacts()` reads `module_name` first, falls back to spec-title regex
- Updated both workflow YAMLs (phase1.yaml, phase2.yaml) to declare the new field

One hiccup: the first `populate_work_items.py` run failed because the substrate schema didn't know about `module_name`. Had to add it to the workflow YAMLs before re-running. This is correct — substrate validates custom fields against the workflow definition.

The GR-014 execution itself had a process management issue — `nohup` backgrounded processes still received SIGTERM. Using `setsid` fixed this. The run completed in ~33 minutes with no pipeline bugs.

I'm confident in the BC-084 fix. The 3 new tests cover the critical paths: custom field takes priority, fallback to spec title works, parenthetical suffix still mangles (documenting the old behavior). The `_extract_module_name_from_spec` function is intentionally kept as a fallback for work items that don't have a `module_name` custom field (e.g., items created by other means).

## Gaps to flag

- **Workflow YAML custom field drift** (`workflows/phase1.yaml`, `workflows/phase2.yaml`): Every new custom field requires updating both YAMLs and a substrate re-registration. There's no validation that the YAML declares all fields the code uses. A schema cross-check test would prevent the "unknown fields" error I hit during populate.
- **Process management for golden runs** (`AGENTS.md`): The bash tool kills backgrounded processes after ~2 minutes. AGENTS.md says to use `&` and `wait`, but `setsid` is actually required. Should update the instructions.
- **`_extract_module_name_from_spec` still exists** (`src/factory/dep_resolution.py:25`): It's a fallback now, not the primary path. But nothing prevents new code from calling it directly instead of using `module_name`. Consider adding a deprecation comment or a test that asserts all dep resolution goes through `resolve_dep_artifacts`.
- **No `module_name` propagation to test_suite/implementation** (`populate_work_items.py`): Only `interface_spec` items get `module_name`. The scheduler copies `dependency_refs` downstream but not `module_name`. If test_suite or implementation items ever need their own module name (they currently don't — they look up their dependency's name), this would need threading. Low risk but worth noting.
