## On the project

The project is hitting the classic phase transition from "does the pipeline work at all?" to "does it work under realistic conditions?" GR-012 exposed that the cert-watch-mini fixture was too simple — every downstream item had either zero or one dep, and the one dep happened to get locked first by luck. The full fixture with 8 items, 3 diamond consumers, and a non-FR module immediately surfaced a real pipeline gap (dep ordering) that mini couldn't catch.

The BC-077 fix is satisfyingly small (~15 lines) because the scheduler already polls on a loop. The architecture of "scheduler creates, runner processes, gate evaluates" means the scheduler is the right place to enforce ordering — it has the dependency graph in `CUSTOM_FIELD_DEPENDENCY_REFS` and it naturally retries on the next poll cycle. No need for topological sort or runner changes.

The non-FR module (`cert_chain_library`) was handled correctly by all pipeline components without any special-casing. That's a good sign — the pipeline doesn't bake in assumptions about work-item purpose.

## On the work done

The fixture changes were straightforward — editing 4 ACs, creating 1 new module, updating 3 dependency lists. The golden run execution was more involved: I initially forgot to start the gate process (only started scheduler + runner), which caused a 3-minute delay before I noticed items sitting in `gating` state. Then the first scheduler process got killed by the bash tool timeout and I had to restart it with `setsid`.

GR-012 results (73% lock rate, 5/8 test_suites escalated) look bad on paper but the root cause was singular: certificate_model processed last. With BC-077 fixed, the next run should defer all downstream creation until certificate_model locks, which means test_suites will be created with the right dep artifacts available. I'm confident the fix is correct but we won't know until GR-013 validates it.

The BC-077 implementation itself was clean — the `_all_dep_specs_locked` guard is a simple early return in `_ensure_downstream_item`. The tricky part was updating the existing dep propagation tests in `test_cross_module_deps.py` which used fake UUIDs. Those tests were testing propagation, not ordering, so they just needed real locked work items instead of string literals.
