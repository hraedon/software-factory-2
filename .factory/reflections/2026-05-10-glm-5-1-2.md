## On the project

The project's architecture is converging on the right shape. The "information gap" diagnosis — that the model couldn't see the types it needed to import, so it fabricated stubs — was confirmed across three consecutive golden runs (GR006a, GR007, GR008) before being fixed. This pattern (diagnose from telemetry, target the root cause structurally rather than adding prompt rules) is exactly what spec principle 8 prescribes: "errors loop back to contract revision, not worker retry."

The inner gate loop (BC-075) is the right design but its impact on this particular fixture was neutral — the remaining failure is a runtime bug (pytest `assert isinstance(result.leaf, Certificate)` fails because the implementer returns `leaf=None`), which mypy/ruff can't catch. This validates Opus's assessment that option #2 (rich workspace) targets the actual root cause for the mypy failures, while option #1 (inner loop) is a general-purpose convergence mechanism that catches lint/format issues but not logic bugs.

The project is now at 367 tests, 0 lint errors, 0 dead code. The test surface for the new code (8 tests across `test_context.py` and `test_pre_gate.py`) is reasonable but doesn't exercise the full inner gate loop end-to-end with a real substrate — that requires a golden run.

## On the work done

The three changes fit together cleanly:

1. **BC-074 (dependency context injection + .pyi stubs):** This was the highest-impact change. The `context.py` change is a simple extension of the existing `locked_interface` pattern — it reads `CUSTOM_FIELD_DEPENDENCY_REFS`, resolves each to its artifact, and injects as `locked_dependency_<module_name>`. The gate change (writing both `.py` and `.pyi`) is a 2-line addition that fixes mypy's treatment of `.py` stubs. Both are "obvious in hindsight" fixes that required the golden-run diagnosis to identify.

2. **BC-075 (inner gate loop):** This was more complex — 80 lines in `runner.py` for `_inner_gate_loop()`, plus a new `pre_gate.py` module. The prompt context reconstruction (deriving new `PromptContext` with accumulated `prior_failures` from the pre-gate diagnostics) is the key design decision. I'm confident the structure is correct but the `PromptContext(frozen=True)` dataclass means I'm constructing a new instance with `prior_failures` list concatenation, which works but is a bit verbose. A `_with_failure()` factory method on `PromptContext` would be cleaner but I didn't want to over-engineer.

3. **GR008/GR009/GR010 golden runs:** Three full pipeline executions validated both fixes end-to-end. The telemetry data is consistent — `implementation_mypy` failure count dropped from "every WI that depends on certificate_model" to zero.

## On what remains

1. **The 33% ceiling on the cert-watch-mini fixture.** One of three implementations still fails (FR-03 file upload, `upload_certificate` returns `leaf=None`). This is a genuine pytest failure that neither option #1 nor #2 fixes. The next structural intervention would be option #3 (let the implementer run its own tests), which is a larger architectural change that requires the channel adapter to provide a Python runtime to the model.

2. **BC-073 (ensure_project_venv robustness).** The partial fix (copy `requirements.txt` from fixture dir) works for golden runs but isn't a general solution. The scheduler should propagate requirements paths through custom_fields, or `ensure_project_venv` should search `<work_item_dir>/requirements.txt`.

3. **Window C items 3.3–3.5 (credentials, budget circuit breaker, notification hook).** These are per the Phase 2 close plan. Credentials infrastructure is the next one in sequence.

4. **Phase 3 channel adapter development.** With `SubprocessChannel` base (BC-061) and inner gate loop (BC-075), adding a new adapter is now ~20 lines of channel code. The K2 adapter would be the natural first one.

## Gaps to flag

- **`_inner_gate_loop` in runner.py** doesn't track duration_seconds for the retry invocations correctly — it adds retry duration to the outer `duration_seconds` but the substrate `SubmitPayload` only records the final duration. This means telemetry will show longer durations than actual wall-clock for inner-gate-retried implementers. Low severity (telemetry is approximate already) but worth noting.

- **`pre_gate.py`** doesn't run pytest (only mypy+ruff). This is by design — pytest needs the test suite file and full workspace setup that the inner loop can't conveniently replicate. But it means the inner loop can give a false sense of confidence. The outer gate still catches everything.

- **The `inner_gate_retries` config field** defaults to 2 but there's no test coverage for the config path (only the `pre_gate` module itself). If someone sets `inner_gate_retries: 0`, the inner loop is skipped entirely, which is correct behavior but untested.

- **GR010 config yaml** uses `inner_gate_retries: 2` but this value hasn't been tested in the golden run configs for the curated fixtures (primary-spec). Only cert-watch-mini was tested. The inner loop adds per-attempt latency (each retry invokes the model again), so `inner_gate_retries: 2` adds up to 2x the model invocation time per implementer claim for WIs that fail the pre-gate.
