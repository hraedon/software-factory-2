# Session Reflection — 2026-05-08

**Work summary:** Attempted Wave 7 (golden-run-002) — the first end-to-end multi-stage pipeline run with real Claude CC. The run failed at the implementation stage due to a cross-work-item module resolution bug in `_run_pytest` and `_run_mypy`. Fixed the bug, filed BC-037 for a separate escalation routing no-op discovered during the failure, wrote post-mortem. 238/238 unit tests pass, lint clean.

---

## On the project

Phase 2 is in a genuinely good state for stages 1–2 (interface_spec → test_suite). Both achieved 100% first-attempt pass rate with real Claude CC. The scheduler worked flawlessly — 30 handoffs with zero duplicate items. The pipeline shape is correct.

The implementation stage is where the architecture's seams show. The gate runs subprocess-based checks (mypy, pytest, ruff) against artifacts that live in separate workspace directories, imported under module names that don't match their filenames. This is the kind of integration gap that unit tests with hand-crafted `tmp_path` artifacts can't catch — you need the actual multi-directory workspace layout to see it. The golden run caught it in ~15 minutes of real execution, which is exactly what golden runs are for.

The escalation routing bug (BC-037) is more concerning than the module resolution fix. The module resolution was a missing integration detail; the escalation no-op is a correctness gap in a load-bearing safety mechanism. The spec says "errors loop back to contract revision, not worker retry" (§3.8), and the escalation is supposed to enforce that after N retries. But the escalation just sets a diagnostic field that nobody reads, allowing infinite retry loops. This needs to be fixed before any production use, and the fix should be simple: transition to `cannot_proceed` on escalation.

## On the work done

The `_run_pytest` / `_run_mypy` fix feels solid. Using temp directories with deterministic module names is cleaner than trying to manipulate PYTHONPATH across workspace directories. The approach is isolated (no side effects on the workspace), correct (both the original filename and `interface.py` are available), and testable (existing subprocess gate tests pass with the new approach).

I'm less confident about the routing-stress fixtures (RS-01, RS-02). They were designed to elicit specific failure modes (mypy type-narrowing failure, pytest boundary-case failure), but we never got to test them because the module resolution bug blocked all implementations. The specs might be too easy or too hard — we won't know until the next golden run. If they don't produce the intended failure patterns, they'll still serve as valid primary items.

The Claude budget consumption was painful. 234 invocations, 87% wasted on an infinite retry loop that should have been caught at attempt 3. The principal should be aware that any gate bug in a multi-stage pipeline will amplify budget consumption by a factor of ~15x (items × stages × retry budget) before the pipeline stalls.

## Gaps to flag

- `src/factory/gate.py:_run_pytest` — the temp directory approach copies the implementation as both its original name and `interface.py`. If a test suite imports from a third module name (not `interface` and not the implementation's stem), it still won't resolve. This is unlikely but not structurally prevented. Consider parsing the test suite's imports and creating symlinks for all referenced local modules.

- `src/factory/gate.py:_run_mypy` — the temp directory has both `interface.py` (implementation) and `interface.pyi` (stub). Mypy should prefer the `.pyi` for type checking and the `.py` for semantic analysis. This works correctly for mypy, but if the implementation diverges from the stub (e.g., different default values, extra attributes), mypy may report confusing errors because it's checking the implementation against its own stub in the same directory.

- `src/factory/gate_process.py:12` — imports `_to_uuid` (underscore-prefixed) from `factory.context`. Noted in prior reflections but still present. This is a minor convention violation that should be cleaned up.

- `tests/test_gate_implementation_subprocess.py` — tests only exercise same-directory artifacts (e.g., `compute.py` + `test_compute.py` in the same `tmp_path`). They don't test the cross-directory import pattern that was the actual failure mode. Consider adding a test that places implementation and test suite in separate subdirectories and verifies the gate still works.

- `golden-run-002-config.yaml` — `claim_ttl_seconds: 600` is generous. With implementation retries taking ~30s per cycle, a stuck implementation could hold a claim for 10 minutes. This is fine for golden runs but will need tuning for production use.

- The `uv.lock` file changed (175 lines added). This is likely from resolving dependencies when running the pipeline. Should be reviewed to ensure no unexpected dependency additions.
