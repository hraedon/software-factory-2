## Gaps and concerns

1. **No MockSubstrate yet.** The current integration tests use a real Postgres. The plan calls for `MockSubstrate` in Wave 6 golden-run testing. The current tests work because substrate is available and the docker-compose Postgres is running, but a CI environment would need Postgres. This is a known gap; the plan mentions MockSubstrate as desirable.

2. **Context derivation currently reads `spec_section` as a string field.** For substrate-sourced test items, `spec_section` points to a section of the substrate spec. The `derive_context` function currently treats it as raw text; for real execution, it needs to resolve that to actual spec content (either by reading from a configured spec file path, or by extracting the relevant section from a larger spec document). This is an expected gap — the runner's context derivation will need configuration for where to find spec content.

3. **The `secondary-spec/spec.md`** dates from Opus's session. It's a well-structured LoB spec (date-range parser) that serves the secondary test set well.

4. **`ClaudeCodeChannel`** invokes `claude-code --print` as a subprocess. This hasn't been tested against a real Claude CC instance. The interface is correct per the plan, but the prompt format and output parsing may need iteration.

5. **BC-002 and BC-003 are implemented but their acceptance criteria** point to tests that are now passing. The BC-003 ACs about crash-before-submit, crash-during-write, and manifest-tampering are fully covered by `test_runner_idempotency.py`.
