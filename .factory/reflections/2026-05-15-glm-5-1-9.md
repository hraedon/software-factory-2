## On the work done

**Confident in:** The four RFC implementations are straightforward and follow existing patterns. The failure_summarizer's local constraint extraction is conservative — it only extracts patterns it can verify from the diagnostic text (import refs, type mismatches, missing symbols, recurring errors). The integrator multi-module context fix is correct and tests exercise the key paths (find other locked items, exclude focal item, infer module name from artifact path).

**Less confident in:** The prompt_audit module's `_ARTIFACT_CONSUMES_FROM_PROMPT` map is manually maintained and could drift from the actual context derivation in `context.py`. If a new artifact is added to a role's `derive_*_context()` function but not to the audit map, the auditor will produce false positives for "orphaned references." There's no mechanical link between the two. The `_DIRECTIVE_PATTERNS` regexes are also manually curated and could miss new directive patterns added to prompts.

The failure_summarizer's `_extract_constraints_locally` is a heuristic. It extracts what it can from raw diagnostic text without calling a model. This is the right tradeoff for Phase 5 (zero cost, deterministic), but the `build_summarizer_prompt()` function exists for future model-mediated summarization when the local approach proves insufficient. The risk is that the local extraction produces vague or redundant constraints that don't actually help the model avoid its prior mistakes — we won't know until the next golden run with outer retries.

The `_gather_other_locked_artifacts` function queries all locked implementations (`page_size=200`) which won't paginate for small projects. If a project has >200 locked implementations, it will miss some. The existing scheduler uses similar patterns with a `query_page_size` config; this function hardcodes 200.

## Gaps to flag

- **`_gather_other_locked_artifacts` hardcodes `page_size=200`.** Should use `config.query_page_size` or paginate. `src/factory/context.py:491-502`
- **`_ARTIFACT_CONSUMES_FROM_PROMPT` in prompt_audit is manually maintained.** If `derive_*_context()` in context.py adds new artifacts, the audit map won't know. `src/factory/prompt_audit.py:83-91`
- **`render_prompt` switching between raw and summarized failures changes `context_hash`.** Existing work items in progress with prior raw-diagnostic context hashes will get a different hash after this change, causing the runner to potentially re-invoke when it wouldn't have before. This is a feature (summarized content = fresh prompt), but it means any in-flight golden run will behave differently after this commit. `src/factory/context.py:550-567`
- **Failure summary local extraction produces English strings, not structured data.** The constraints are prose bullets, not machine-readable tags. A model receiving "Import references seen: certificate_model" must parse the English to know which module to check. `src/factory/failure_summarizer.py:60-137`
- **No `pytest.mark.integration` tests for prompt_audit against real prompts.** The `test_audit_against_real_prompts` test reads real prompt files but doesn't assert specific conflicts — it just checks returns aren't empty. A real conflict (like the BC-050 typing.Union case) should be a regression test. `tests/test_prompt_audit.py:113-118`
