## On the project

The codebase continues to be well-organized and disciplined. The breadcrumb system is genuinely useful — I was able to pick up three items, understand each one from the breadcrumb file alone, and resolve them without needing to ask questions. The AGENTS.md orientation instructions work.

The integration test gap identified by BC-063 was real. The existing integration tests only covered `interface_spec` lifecycle and raw state machine transitions. Adding tests for test_suite processing, implementation processing, scheduler DAG creation, channel failure retry, and crash recovery against real Postgres was straightforward because the factory functions (`process_work_item`, `process_gate_item`, `_ensure_downstream_item`) have clean interfaces. The `_StubChannel` pattern from `test_pipeline_idempotency.py` was easy to adapt.

The substrate syntax error was a surprise. It's in the `Substrate.__init__` constructor — the most fundamental code path. How did it pass any testing? Because the integration tests use `Substrate.create_project()` (a classmethod) and InMemorySubstrate, neither of which goes through the broken `__init__` directly. The `build_failure_corpus.py` script is the only factory code that calls `Substrate(dsn, project, key_path)` directly. This means the substrate has been broken for direct-connection use since whenever that indentation bug was introduced.

## Gaps to flag

- **Substrate `__init__` indentation bug** (`/projects/substrate/src/substrate/__init__.py:138`) — I fixed it in this session but it's in the substrate repo, not the factory repo. If the substrate gets a revert or someone else checks out a different version, this will break `build_failure_corpus.py` again silently (it only fails at import time when the script runs, not during `make check`). Should be tracked as a substrate breadcrumb.
- **`_StubChannel` duplication** — `test_integration_pipeline_shapes.py` and `test_pipeline_idempotency.py` both define similar stub channel classes. Could be extracted to `tests/conftest.py` or a shared helper. Low priority but worth noting.
- **BC-063 `make replay` deferred** — The breadcrumb proposed a `make replay` target for replaying golden run artifacts through real substrate + real gates. This was deferred. If InMemorySubstrate divergence resurfaces, this is the next mitigation.
- **Integration test module scope** — The `real_sub` fixture in `test_integration_pipeline_shapes.py` is module-scoped, meaning all 8 tests share one substrate project. If tests fail, they may leave the project in a dirty state that affects subsequent tests. The existing integration tests (`test_phase2_workflow_roundtrip.py`) use the same pattern, so this is consistent, but it's a fragility worth knowing about.
