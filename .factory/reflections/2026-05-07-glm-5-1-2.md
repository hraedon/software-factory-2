## On the project

The factory's Phase 1 code is in better shape than the test suite suggested. The three bugs I found and fixed — diagnostics schema mismatch, resume path, and .pyi stub bypass — were all at seams between individually-tested components. None of them would have been caught by the existing tests because the tests validated each component in isolation without exercising the connections. This is the classic integration gap: each piece works, the contract between them is untested.

The most concerning pattern is that `router.py` is dead code — well-tested dead code, but dead nonetheless. `gate_process.py` hardcodes its own transitions and never calls `route()`. The two have drifted to different diagnostic schemas. I aligned them, but the architectural question (wire it in now, defer, or delete) is a principal decision.

The structural-semantic gates I added (BC-013, option c) feel right for Phase 1 but will need extension for each new role. The AC-reference substring check is the weakest gate — `ac_id not in content` catches "AC-01" in comments or strings with no structural binding. The `_check_structural_semantics` function's docstring-AC binding mitigates this, but `_check_ac_references` still runs as a raw substring check afterward. BC-016 captures this design question.

## On the work done

The most impactful change was the diagnostics schema fix. Gate failures were being recorded with `messages` (plural, a list) but `derive_failures` was reading `message` (singular, a string). This means every retry cycle was operating without failure context — the implementer never saw *why* the gate rejected them. This is a spec-level correctness bug, not a cosmetic inconsistency. The fix adds both fields, plus `payload` alongside `custom_fields` so `derive_failures` can read per-event diagnostics.

The `.pyi` stub bypass was embarrassing but straightforward: the code literally did `if suffix == ".pyi": pass`. The gate's own tests only tested `.py` files, so the bypass was invisible. `.pyi` is the primary artifact type.

The resume-path bug was identified but not fully closed by test — BC-014 captures the integration-gap need. The fix (passing full path instead of filename) is correct, but the resume-and-submit path still has zero integration coverage.

I'm confident in all the bug fixes. The new tests for `derive_failures` and `claude_code_channel` are solid — they exercise the actual function contracts, not just serialization trivia. The structural-semantic tests cover the edge cases well (no defs, missing return types, no parameters, detached ACs, self params).
