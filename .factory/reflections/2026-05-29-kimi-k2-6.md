## On the project

The project is at a tense but productive inflection point. Phase 6.2 has moved from "web-service archetype is failing" to "we now have an execution-based falsification instrument." The RFC-038 conformance gate is the real deal: it caught every stub artifact from GR-048, and the AC-translation is deterministic enough that fixing a single regex (`Location:` header) is sufficient to close a gap. The gate is not yet integrated into the pipeline's *happy path* for real runs because GR-049's gate_process logs show `conformance_spec_parse_failed` when `spec_section` is a markdown file (the custom field stores `spec.md` content, not `spec.yaml`). That bug is fixed in the code but not yet re-validated in a live run.

The decomposer prompt rewrite (Phase C) is the biggest subjective bet of the session. I replaced the Phase B "semantic naming + FR grouping" section with a denser "deliverable-altitude / walking skeleton" section. The prompt now explicitly forbids `error_formatter` library modules, requires FastAPI endpoints in modules owning HTTP ACs, and demands DB-backed queries in modules owning persistence ACs. This is a fundamentally different decomposition target. Whether models actually follow it is an open question; the prompt is the hypothesis, GR-050 is the falsification.

I fixed this *after* the run, so the gate logs from GR-049 reflect the bug. The fix is solid but needs a re-run to confirm.

**What I'm confident in vs. not:**

## Gaps to flag

1. **`_extract_acs_from_spec` markdown fallback is new and lightly tested.** `tests/test_gate_conformance.py` has 31 tests but most use YAML fixtures. Add a test for the markdown `- `AC-NN`: condition` format. (`src/factory/gate/conformance.py:21-76`)
2. **`agent_golden_run.py` idle timeout is still too aggressive for full pipeline runs.** 30 × 30s = 15 min max idle. The gate evaluation alone can take 5-10 min per item, and with many items the pipeline is legitimately idle between evaluations. The wrapper SIGTERMed a healthy run. Consider raising `max_idle_cycles` or making it configurable. (`scripts/agent_golden_run.py:382`)
3. **`populate_work_items.py` with `--fixtures` on a directory containing only `spec.yaml` and `spec.md` creates a monolithic `spec` work item instead of decomposed modules.** This is expected behavior when no `.md` fixtures exist, but it's a footgun for url-shortener. Either decompose automatically on `--fixtures` if the dir contains a `spec.yaml`, or document that `--spec-yaml` must be used for decomposition. (`populate_work_items.py`)
4. **No telemetry for `conformance` gate outcomes.** `telemetry.py` counts `outcome_e2e` gate events but does not yet report `conformance` pass/fail separately. If RFC-038 is adopted as the primary outcome gate, the telemetry tables need a column. (`src/factory/telemetry.py`)
5. **`agent_golden_run.py` log directory is inside the repo (`REPO_ROOT/.factory/logs/`).** When `--no-cleanup` is used, logs accumulate in the repo. This is acceptable but creates untracked files risk. Not urgent.
6. **The `requirements.txt` in url-shortener fixture installs `httpx` but the gate venv doesn't always have pip available.** In the test workspace, `python_executable` defaults to the gate venv python, but if that venv wasn't created correctly (e.g. `.venv-gate` missing pip), pip install fails. The conformance gate logs a warning but continues. This is graceful degradation, but it means some runs may fail with ImportError instead of stub-failure. (`src/factory/gate/conformance.py:388`)
