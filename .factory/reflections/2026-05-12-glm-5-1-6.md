## On the project

The project is in strong shape for a Phase 3 exit attempt. The three-layer metric framework in the spec is a significant improvement — previous discussions about "first-attempt rate" were conflating contract quality (Phase 3's concern) with adversarial validation (Phase 4's concern). The spec amendment is clear and operational: any future golden run now has pass/fail criteria, not vague targets.

BC-130 revealed a real gap: the spec lint was supposed to be BC-127's core value, but it couldn't actually parse the cert-watch fixture specs because it only handled `## Acceptance Criteria` bulleted format. The real specs use `## AC-NN: Title` heading-per-AC format. This is a pattern I've seen before in this project — features built against mental models of input data rather than actual test data. The fact that the cert-watch fixtures were always available but never run through the lint during development is a reminder that integration tests need to exercise real fixtures, not just synthetic ones.

The telemetry exit-criteria summary is a clean addition. It prints a clear PASS/FAIL table against the Phase 3 thresholds. This will make GR-020's go/no-go decision trivial — run telemetry, read the summary, done.

## On the work done

The spec_lint refactor was the most substantive change. Replacing `_extract_ac_section` + `_parse_ac_bullets` with a unified `_extract_acs()` that handles both formats was straightforward once I understood the fixture structure. The dead-code bug on line 74 (`current_id is not None` as a bare expression) was caught by inspection during the rewrite — it would have caused the parser to skip non-AC headings that terminate an AC section, leading to body text being appended to the wrong AC. Real specs like `wi_fr02_tls_scan.md` have `## Dependencies` sections between AC headings, so this would have produced corrupted AC bodies.

The telemetry `ExitCriteriaMetrics` and `format_exit_criteria_summary` additions are functional but I'd flag one design choice: the "first-attempt mechanical-gate pass rate" currently prefers inner-gate data and falls back to outer-gate data only when no inner-gate events exist. This is correct for Phase 3 where inner-gate data is the clean signal, but the fallback might produce misleading numbers in Phase 2-only contexts. Worth noting but not worth changing now.

BC-120 deferral to Phase 4 feels right. The structured `cannot_proceed` for interface amendment is architecturally sound but operationally premature — we haven't seen the pattern in real runs yet, and adding telemetry for it in Phase 4 when jury gates exist makes more sense.

## Gaps to flag

- **spec_lint heading-per-AC parser**: The `_extract_acs` function has a subtle behavior — if a spec has BOTH `## AC-NN:` headings AND a `## Acceptance Criteria` section, the heading-per-AC parser wins and the bulleted section is ignored. This is correct for Phase 3 fixtures but might surprise someone who mixes formats. Not worth changing now.
- **telemetry.py ExitCriteriaMetrics without tests**: The new `compute_exit_criteria` and `format_exit_criteria_summary` functions have no dedicated unit tests. They'll be validated by GR-020's telemetry output, but a unit test exercising the metrics against a mock substrate would be more robust. Low priority since the logic is straightforward.
- **Historical GR data may be gone**: BC-126 measurement requires ≥100 work-item rows across ≥6 GRs. The substrate databases from GR-001 through GR-018 may no longer exist (they use `--reset`). This means the analysis might only have GR-020 data, which undermines the correlation requirement.
- **`_extract_acs` body collection for headings**: When an AC heading is followed by a non-AC heading (like `## Dependencies`), current code correctly terminates that AC's body. But if a spec ends without a trailing newline, the last AC might miss its final line. This is a cosmetic edge case; real fixtures end with newlines.
