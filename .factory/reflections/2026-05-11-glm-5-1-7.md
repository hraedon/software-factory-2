## Gaps to flag

- **`_extract_module_name_from_spec` is the only module name source for dep resolution** (`dep_resolution.py:25-34`). There's no fallback to a canonical source. The fixture filenames (`wi_certificate_model.md` → `certificate_model`) are the ground truth but aren't stored anywhere accessible to the gate at runtime.
- **`populate_work_items.py` doesn't set `module_name` or `label` in custom_fields** for the work items it creates. If it did, BC-084's fix would be trivial — dep_resolution reads `custom_fields["module_name"]` instead of parsing the spec title.
- **No diagnostic logging in `_run_pytest_collect`** — when collection fails, the gate returns diagnostics but doesn't log the dep resolution results or the files that were copied to the temp dir. Adding a debug-level log of `dependency_pyi_paths` would have saved 20 minutes of manual reproduction.
- **BC-078 still open** — the 80%+ lock rate framing is measured on single-module fixtures. Once BC-084 is fixed and a full-DAG run succeeds, the principal should decide what the exit criteria actually are.
