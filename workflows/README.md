# Workflow Runbook — Phase 1

First-run sequence for standing up SF2's `software_factory` workflow against substrate.

## Prerequisites

- Postgres 15+ running (default: `localhost:5432`, db `substrate_test`)
- HMAC key file at `tests/test_keys.json` (generated by substrate)
- `claude` binary on PATH (`claude --version` → 2.x+)
- Python 3.12+ with uv

## Setup (one-time per project)

```bash
# 1. Register the workflow
uv run python -c "
from substrate import Substrate
sub = Substrate.create_project(
    'postgresql://substrate_test:substrate_test@localhost:5432/substrate_test',
    'sf2_test',
    'tests/test_keys.json',
)
sub.register_workflow_file('workflows/phase1.yaml')
sub.close()
"

# 2. Populate work-items from fixture specs
uv run python populate_work_items.py --project sf2_test

# 3. Verify work-items exist
uv run python -c "
from substrate import Substrate
sub = Substrate(
    'postgresql://substrate_test:substrate_test@localhost:5432/substrate_test',
    'sf2_test',
    'tests/test_keys.json',
)
page = sub.query_work_items(workflow_name='software_factory', page_size=20)
for wi in page.items:
    print(f'{wi.work_item_id}  {wi.work_item_type}  {wi.current_state}')
sub.close()
"
```

## Running the factory

Two separate processes, coordinated via substrate:

```bash
# Terminal 1: Worker — claims items in 'new', invokes claude, submits
uv run factory-run

# Terminal 2: Gate process — claims items in 'gating', runs mechanical gates
uv run factory-gate
```

**Order matters:** start the worker first (it submits items into `gating`); the gate process picks them up from there.

**Filesystem constraint:** `artifact_path` is stored as a host-absolute path. The runner and gate processes MUST run on the same host with the same `workspace_root`. Do not split them across containers or machines in Phase 1.

## Before the first batch: manual smoke test

Claude `--print` headless mode returns text to stdout, not files. The channel adapter extracts artifacts from fenced code blocks. Before running the full batch, verify Claude's output format on one fixture:

```bash
cat tests/fixtures/primary-spec/01-acquire_claim.md | claude --print --output-format text --max-turns 1
```

Expected output: a single ` ```python ... ``` ` fenced block containing a valid `.pyi` stub. Confirm there is no prose preamble before the fence and no postscript after it. If Claude emits two separate code blocks, the extractor will only capture the first — file a breadcrumb and switch to `--allowedTools Write` mode as a fallback.

## Post-run telemetry

```bash
uv run python report.py --project sf2_test
```

Prints per-work-item attempt count, terminal state, gate diagnostics, context_hash, category breakdown, and exit-criteria verdict.

## Monitoring

```bash
# Check work-item states
uv run python -c "
from substrate import Substrate
sub = Substrate(
    'postgresql://substrate_test:substrate_test@localhost:5432/substrate_test',
    'sf2_test',
    'tests/test_keys.json',
)
for state in ('new', 'in_progress', 'gating', 'locked', 'cannot_proceed'):
    page = sub.query_work_items(
        workflow_name='software_factory',
        current_states=[state],
        page_size=50,
    )
    print(f'{state}: {len(page.items)} items')
sub.close()
"
```

## Shutdown

Send SIGTERM/SIGINT to each process. The worker releases its claim on next loop iteration; the gate process exits cleanly.

## Resuming after crash

Just restart `factory-run`. §9.12 idempotency: if a prior attempt wrote a valid manifest + artifact, the runner resumes from it without re-invoking Claude. Corrupt attempts are quarantined.

## Expected results (Phase 1 exit criteria)

- 10 primary items: ≥9/10 reach `locked` on first attempt
- 1 adversarial item: reaches `cannot_proceed` (structured failure)
- Categories: ≥2/3 pass in each shape (pure-interface, error-taxonomy, ADT-validation)

## Troubleshooting

| Symptom | Likely cause | Fix |
|---|---|---|
| Worker exits with "claude not found" | `claude` binary not on PATH | `export PATH="$HOME/.local/bin:$PATH"` |
| Worker exits with timeout | Claude takes >10min per item | Increase `timeout_seconds` in config |
| Items stuck in `new` | Worker process not running | Start `factory-run` |
| Items stuck in `gating` | Gate process not running | Start `factory-gate` |
| Items cycling `new` → `gating` → `new` | Gate failing (diagnostics in custom_fields) | Check `artifact_path`; view the `.pyi` artifact |
| Worker can't claim | Claim TTL not expired or item claimed by another actor | Check `sweep_expired_claims()` or wait for TTL |
