## On the project

The pipeline infrastructure is done. That's the real takeaway from this session. Three stages, three roles, scheduler, gate, escalation — all working without human intervention. The codebase feels clean and well-decomposed. The Channel protocol is a good abstraction — adding a new channel (BC-040) is straightforward because the interface is narrow.

The one part that feels fragile is the resume logic in `runner.py`. The `find_resumable_artifact` → immediate submit path was designed for crash recovery but activates on gate failures too. It's not catastrophic (items still escalate and terminate) but it wastes invocations resubmitting the same bad artifact. This will matter more when we're paying per-token or rate-limited.

The prompts directory (`src/factory/prompts/`) is underinvested relative to the infrastructure. The implementer prompt doesn't mention modern typing conventions, which caused 9/10 implementation failures. This is the next leverage point — the infrastructure is ready, the prompts aren't.

## On the work done

The `_run_pytest_collect` bug was satisfying to find and fix. It was the same class of bug as the original module resolution issue from Session 10 — subprocess gates operating on files in isolation without setting up the import path. The fix was clean: temp directory with `interface.py` alongside the test suite, same pattern as `_run_pytest` and `_run_mypy`. I'm confident in this fix.

The model selection addition (`RoleConfig.model` → `--model` flag) was straightforward. The claude CLI supports `--model` as an alias, so passing `sonnet` Just Works. Clean change, no regressions.

The golden run itself was tedious to monitor — 28 minutes of checking logs every 2-3 minutes. The processes kept getting killed by bash timeouts until I figured out the `setsid` approach. For future runs, a proper process supervisor (or at least a `--once` flag that processes all available items and exits) would be much more ergonomic than long-running poll loops.

The postmortem was honest. 2/12 implementations locked sounds bad, but the 10 failures are all the same class of problem (ruff style violations on mechanically correct code). One line in the implementer prompt or two lines of auto-format would likely flip most of those.

## Gaps to flag

- **`runner.py:151` — `find_resumable_artifact` doesn't check gate history.** Items with prior `gate_fail` events get their artifact resubmitted unchanged. Should check substrate for gate_fail events before deciding to resume. Part of BC-039.

- **`gate.py:_run_pytest_collect` temp dir doesn't copy `.pyi` for mypy.** The collect gate copies `interface.py` (from `.pyi` content) for pytest discovery. This works at runtime because Python imports `.py` files. But the `.pyi` file isn't placed alongside for any hypothetical type-checking during collection. Not a current issue since collect is syntax-only, but inconsistent with `_run_mypy` and `_run_pytest`.

- **`runner.py:345-347` — hardcoded `ClaudeCodeChannel` import in `main()`.** BC-040 proposes a channel factory, but until that's implemented, the runner can only use Claude. Config says `channel: opencode` but the runner ignores it.

- **No `--once` / `--max-items` flag on worker or gate.** The poll-loop design means every golden run requires process supervision and manual killing. A `--once` flag that processes one item and exits, or `--max-items N`, would make testing much faster.

- **The implementer prompt doesn't mention ruff conventions.** `src/factory/prompts/implementer.md` is silent on import sorting, modern typing syntax, and formatting. This is the direct cause of 9/10 implementation failures. BC-039 addresses it.

- **`golden-run-002-log.md` is stale.** It describes the Session 10 failure (0/15 implementations). The Session 11 (this session) results are in `golden-run-003-log.md`. The numbering is confusing — 002-log describes run 001's failure, 003-log describes run 002's re-attempt. Consider renaming or consolidating.
