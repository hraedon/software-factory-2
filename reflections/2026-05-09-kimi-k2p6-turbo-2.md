## On the project

The project is in a healthy but precarious state. The telemetry bundle (Window A) is genuinely well-architected — event schemas with forward-compatible unknown-field warnings, prompt template hash tracking, latency instrumentation, and a `--verify` CLI. The `make golden-run` target codifies the runbook. These are force-multipliers.

But the architecture has a structural blind spot: it was validated on single-module fixtures (each interface_spec is self-contained). The cert-watch workload is the first multi-module workload, and it immediately exposed that the scheduler's handoff mechanism and the gate's temp directory setup only handle single `interface_ref` links. The dependency graph is flat, not a DAG. This isn't a "bug in the new code" — it's a missing feature that the curated fixtures never exercised.

The spec's phasing (§10) is the project's best defense against this kind of surprise. Phase 2 was supposed to validate the pipeline shape before adding fleet complexity. It did — and the shape has a gap. Better to discover it here than in Phase 4 with three channels and a jury.

## On the work done

The telemetry refactor is the work I'm most confident in. The event schema dataclasses, the round-trip tests, the replay fixture regression test — these are solid. The latency tracking and prompt hash telemetry are additive and don't break existing behavior.

The assertion-counting gate (`_check_assertion_count`) is simple but effective. I'm less confident it won't have false positives on complex test patterns (assertions inside helper functions, parametrized fixtures). The AST walk only counts `ast.Assert` nodes directly inside test functions. A test that uses `pytest.raises()` without an explicit `assert` would pass this gate but might still be vacuous. This is acknowledged in the plan as a "cheap filter, not a complete defense."

The venv helper (`ensure_project_venv`) uses `shutil.rmtree` on stale venvs before recreating, which is correct but destructive. The hash-based cache works. I did not test the `uv` fallback path (no `uv` in this environment), so the `python -m venv` path is the only one exercised.

GR006a execution revealed the cross-module bug cleanly. The telemetry table shows test_author at 0% first-attempt pass on `test_suite_collect` for the two multi-module items. The criteria tests (`test_gr006a_criteria.py`) correctly fail when results are present, and skip when absent. This is exactly the accountability mechanism the plan designed.

## Gaps to flag

- **tests/test_gr006a_criteria.py reads from `/tmp/sf2-gr006a/`** — an absolute path outside the repo. If the workspace is cleaned or moved, the criteria tests will skip rather than fail, which is correct but means the binding gate only works on the machine where the run happened.
- **`_check_assertion_count` AST walk** (`src/factory/gate.py:269`) does not traverse into nested function definitions or `with` block context managers. A test function that delegates assertions to a nested helper will incorrectly pass the zero-assertion check.
- **`GateResult.skipped` field** (`src/factory/gate.py:46`) was added for the behavioral gate stub but has no consumer in telemetry or reporting. If behavioral gates become real, telemetry needs to distinguish skipped from passed.
- **`populate_work_items.py --fixtures` assigns dummy AC IDs** (`["AC-01"]` for every custom fixture). The AC extraction from spec text is not implemented for arbitrary fixtures. For GR006a this was fine (the test_author prompt includes the full spec text), but for larger workloads the AC list should be parsed from the markdown.
- **Behavioral gate Playwright test imports `uvicorn`** but there is no `uvicorn` dependency in the project. The test is `@pytest.mark.skip` so it doesn't run, but when the gate is implemented, the dependency needs to be added.
- **Channel composition refactor (BC-061)** remains unaddressed. The plan says "do not write a 3rd channel adapter until this lands." If Phase 3 starts with K2/GLM/DeepSeek adapters before BC-061, the code duplication will multiply.
