## On the project

SF2 is in good shape for Phase 2 mid-construction. The test suite is now disciplined — `make check` is a single command that runs ruff lint + format check + pytest, and 218 tests pass cleanly. The Kimi-recommended formatting baseline removes a whole class of future diff noise.

The substrate coupling is the single biggest structural risk. ## On the work done

The cannot_proceed double-release bug was a real find. When the channel returns `error_message="cannot_proceed"` but no JSON file exists in the output directory, the code fell through to `release_claim`, but the claim was already released by the earlier `transition("claim")`. Fix: fall through to `channel_fail` transition instead, which is the correct behavior (record the failure and return the item to `new` state).

The BC-040 alignment was tricky. I initially "fixed" InMemorySubstrate to support composable filters (work_item_id + transition), then realized this was BC-040's *original bug* — the real backend enforces "exactly one filter dimension." The correct resolution was to make InMemorySubstrate match the real backend, then fix SF2's tests to not use composite filters. This required a new `events_by_transition` helper in `_helpers.py`. The right long-term fix is BC-030: make the real backend support composable filters via AND-composition in SQL.

The test files I wrote for gate_process and runner coverage (test_runner_coverage.py) were more frustrating than productive. Phase 2 work-item types (`test_suite`, `implementation`) require the `phase2.yaml` workflow which has different role constraints. The setup is complex — each test needs to register roles, create parent work items with UUID-string refs, transition through multiple states before the code under test can even run. I got 4 good tests (role_for_type, cannot_proceed-no-json) but the gate_process coverage tests hit too many substrate workflow constraints. I opened BC-031 for the remaining gap.

## Gaps to flag

- **`_handle_invoke_failure` line 262** (now 269-ish after formatting) was a real double-release bug. The fix is correct (`channel_fail` transition instead of bare `release_claim`), but this path is only reachable when `cannot_proceed` is the error message but no JSON file exists. The happy path (JSON file present) and the other failure paths (timeout, exit code) were already tested. Only this edge case was uncovered.

- **`substrate._testing.drop_project_schema`** is still imported from a private module in `conftest.py` and `test_phase2_workflow_roundtrip.py`. If substrate moves or renames this function, SF2's integration tests will leak Postgres schemas. Not blocking but a ticking coupling bomb.

- **`test_runner_coverage.py` and `test_gate_process_unit.py`** were created but gate_process_unit was deleted because the Phase 2 workflow setup was too complex. The gate_process coverage sits at 54% with the uncovered lines being `main()`, `gate_loop` signal/poll, and `run_gate`. These need integration-level testing.

- **`conftest.py:WORKFLOW_V2_PATH`** was added but the `mock_substrate_v2` fixture is only used by `test_runner_coverage.py`. If more Phase 2 tests are added, they'll need this fixture — consider making it a standard fixture.
