## On the work done

The core bug (artifact.pyi → artifact.py instead of certificate_model.py) was satisfying to find and fix. It required understanding the full dependency resolution chain: `_resolve_dependency_refs` → `_copy_dependency_pyis` → temp directory. The fix of threading `(module_name, Path)` tuples through the chain is clean and the `_extract_module_name_from_spec()` regex is simple. I'm confident this is correct — the 17 tests and GR007 end-to-end validation prove it.

The `populate_work_items.py` role transition fix was a minor but real blocker that took three attempts: `factory-setup` had no role → `interface_architect` with `actor_metadata` → removed `release_claim()` call. Painful but straightforward.

The certificate_model spec ambiguity (AC-09 "must raise" vs AC-08 union return type) was caught by Kimi K2 refusing to produce the interface spec. This is actually good model behavior — the spec had a genuine contradiction. The fix (change "raise" to "return") makes AC-08 and AC-09 consistent.

The `requirements.txt` copy fix in `populate_work_items.py` is a partial solution to BC-073. The real issue is that `ensure_project_venv()` only checks `<workspace_root>/requirements.txt`, not per-item or per-fixture paths. The copy-from-fixture approach works for golden runs but won't scale for real workloads with different dependency sets per work item.

## Gaps to flag

- `src/factory/venv.py:31` — `ensure_project_venv()` creates venv at `<project_dir>/.venv` but only checks `<project_dir>/requirements.txt`. If populate doesn't copy the file, mypy/pytest gates silently fall back to `sys.executable` which lacks project dependencies.
- `src/factory/gate_process.py:114` — `_resolve_dependency_refs()` does a `sub.get_work_item()` for every dependency ref, which is N queries per gate evaluation. Fine for 1-2 deps, but could be slow for larger dependency graphs.
- `src/factory/gate_process.py` — `_extract_module_name_from_spec()` uses a regex on the spec title to derive module names. This convention depends on spec authors writing `# Interface Specification: <Name>` headers consistently. If a spec title contains special characters, the regex could produce invalid Python identifiers.
- `golden-run-007-config.yaml` — `use_project_venv: true` is set but only works if `requirements.txt` is in the workspace root. This coupling is fragile.
- `src/factory/opencode_channel.py:63` — `_family_override` is set on `self` per-invocation, which is a latent race condition if the channel were ever used concurrently (noted in BC-044, marked resolved but the `_family_override` attribute is still there).
- The telemetry event-matching logic still reports "unknown" gate names for `gate_pass` events, meaning the per-gate pass rate table has inflated "unknown" rows. Known since GR004, not yet fixed.
