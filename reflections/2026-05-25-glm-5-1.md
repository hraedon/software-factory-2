## On the project

This is a well-structured pipeline project with strong convention adherence — constants centralized in `constants.py`, no inline defaults per AGENTS.md, RFC-driven development, breadcrumb-based defect tracking. The codebase is surprisingly clean for its size; the worst issues I found were path traversal rather than logic bugs, which speaks to the quality of prior review passes. The inner-gate / pre-gate / gate architecture is particularly clean — the separation of concerns between runner, gate, and scheduler processes is good engineering.

The one area that feels genuinely fragile is the substrate dependency. Every module imports from `substrate` as if it's a stable library, but the API surface is custom and in-memory test doubles mask real DB behavior. The `_safe_artifact_path` function I found was doing half the job — blocking `..` but allowing absolute paths — which is exactly the kind of "close but not quite right" that passes review by eye but fails under adversarial scrutiny.

## On the work done

**High confidence:**
- Path traversal fixes in workspace.py and dep_resolution.py are straightforward and well-tested (14 tests in test_path_traversal.py)
- Process group kill guard (pgid == pid before killpg) is a clear safety improvement
- FR-ID regex unification (matching `FR-CERT-01` style IDs in addition to `FR-01`) is clearly correct
- Code quality cleanup (removing duplicate yaml import, replacing `__import__('time')`) is trivially safe

**Medium confidence:**
- The `_safe_rmtree` /tmp prefix guard in agent_golden_run.py is the right principle but could be tighter. The /tmp/ convention matches the project's established pattern (workspace_root is always /tmp/sf2-golden-*), but if someone changes the workspace_root convention, the guard would need updating. I considered checking against the configured workspace_root instead, but that would require passing the config through — more invasive for a script.

**Lower confidence:**
- I did not fix the absolute-path acceptance in `_safe_artifact_path` because the normal operation of the pipeline stores absolute paths (e.g., `/tmp/sf2-golden-022/.../attempt-0001/iface.pyi`) and rejecting them would break the test suite and production. The right fix is workspace-root containment checking at the actual read sites (in dep_resolution.py and gate_process.py), but that requires threading `workspace_root` through more function signatures. Flagged as a gap below.

## On what remains

1. **Workspace root containment for artifact reads** — `_safe_artifact_path` currently allows absolute paths because that's the production pattern, but a defense-in-depth check at `read_text()` call sites would prevent a compromised substrate from injecting paths like `/etc/shadow`. This requires threading `workspace_root` through `resolve_dep_refs_for_context` and `_resolve_ref_artifact`.

2. **agent_golden_run.py REPO_ROOT hardcoded to `/projects/software-factory-2`** — should be `Path(__file__).resolve().parent.parent` for portability.

3. **FactoryConfig default `claim_ttl_seconds=300` doesn't match the operational standard of 600** used in all golden runs from GR-002 onward.

4. **`_validate_config` in agent_golden_run.py defaults `attempt_threshold` to 999** when missing from config, which is misleading for a safety-critical field whose hard limit is 3.

5. **test_gr006a_criteria.py and test_gr015_criteria.py always skip** — they depend on `/tmp/` golden run output files that don't persist. Either convert to integration tests or remove.

6. **phase_defaults.py has hardcoded model identifiers** like `"fireworks-ai/accounts/fireworks/routers/kimi-k2p6-turbo"` in 9 places — a "string constant gravity" violation per the project's own AGENTS.md conventions.

## Gaps to flag

- **`agent_golden_run.py:36`** — `REPO_ROOT = Path("/projects/software-factory-2")` is an absolute path that only works on this specific machine. Should derive from `__file__`.

- **`config.py:94`** — `claim_ttl_seconds=300` default doesn't match the operational standard of 600 used in all golden run configs.
