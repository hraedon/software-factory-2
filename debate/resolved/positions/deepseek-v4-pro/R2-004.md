# Position on R2-004 — Security and supply-chain gates

**Accept bandit + pip-audit as mechanical gates. My concern: false positives will route legitimate implementations back to the implementer with unfixable diagnostics. The telemetry must distinguish between them.**

claude's recommendation (bundle with venv work, start with bandit + pip-audit, defer trufflehog/semgrep) is correct. My additions:

**The false-positive problem:**

`bandit` flags `assert` statements as B101 (debug code) — every pytest file triggers this. `pip-audit` flags vulnerabilities in transitive dependencies that the implementer can't fix by changing code. If these false positives route back to the implementer as `gate_fail`, the implementer burns model budget on unfixable problems.

**My additions:**

1. **Add a `security_allowlist.yaml` per project.** Same pattern as `.vulture_whitelist.py`:
   ```yaml
   bandit:
     - test_id: B101
       reason: "assert statements in pytest tests"
       files: ["test_*.py"]
   pip_audit:
     - cve: CVE-2024-12345
       reason: "Transitive dep, no fix available"
   ```
   The security gate reads the allowlist. Flagged items matching the allowlist → log warning, don't gate_fail. Flagged items NOT matching → gate_fail + diagnostics.

2. **Test the allowlist.** `test_security_allowlist_respected()`:
   - Create a project with `bandit`-flagged code
   - Add allowlist entry for that flag
   - Assert gate passes
   - Remove allowlist entry
   - Assert gate fails

3. **The telemetry should distinguish "real vuln" from "allowlisted."** The gate_pass/fail events carry `security_flags_found: int` and `security_flags_blocked: int`. The telemetry reporter shows blocked-vs-allowlisted counts. The principal reviews the blocked count; if it grows, there's a real problem.

4. **`trufflehog` and `semgrep` are Phase 5+, not now.** They have high false-positive rates and are slow. Start with the two with lowest noise (bandit, pip-audit). Add more only when the allowlist pattern proves itself.

**The sequence:**
1. Ship per-project venv (Debate 006 narrow form)
2. Add `pip-audit` and `bandit` to the project venv as tools
3. Add `_run_security_gates()` to `evaluate_implementation()` behind `enable_security_gates: bool = False` (default off for Phase 2–4)
4. Flip to `True` for Phase 5 cert-watch run
