# NEW-001 — Prompt version in ActorMetadata for comparable golden runs

**Problem:** The telemetry table says "87% implementation pass rate" but doesn't say "with prompt version v3." If the implementer prompt changes between GR004 and GR005, the pass-rate difference is uninterpretable — is the model better, or did the prompt change?

spec §9.6 says "Role system prompts are code" and "Updating a convention is a code change, reviewed and committed, with full history." But the telemetry event doesn't capture *which* version of the prompt ran. Two golden runs with different prompt versions produce telemetry rows that look comparable but aren't.

**This directly threatens Phase 3 fleet-placement decisions.** Phase 3 adds K2/GLM/DeepSeek/Gemini channels and compares their pass rates to Claude's GR004/005 baselines. If the prompts changed between baseline collection and fleet comparison, the comparison is invalid.

**Position:** Add `prompt_version` to `ActorMetadata` on every channel invocation. The version is derived from the prompt file's git hash (or content hash if git is unavailable). Add a CI test that asserts `prompt_version` is present in all `submit` events from golden runs.

**Concrete design:**

1. `constants.py` or `config.py` — `derive_prompt_version(prompt_path: Path) -> str` computes `git log -1 --format=%h -- <prompt_path>` or SHA-256 of file content.

2. `runner.py:process_work_item()` — passes `prompt_version` to the channel adapter, which includes it in `ActorMetadata`.

3. `test_prompt_version_in_telemetry()` — replays golden-run events, asserts every `submit` event has a non-empty `prompt_version` in actor_metadata.

4. `telemetry.py` — the pass-rate table gains a `prompt_version` column. Rows with different prompt versions are separated (or flagged with a warning).

**Cost:** ~30 lines of Python + ~20 lines of test. Half a day.

**Why this matters now:** The prompt files (`interface_architect.md`, `test_author.md`, `implementer.md`) have already been modified multiple times across sessions (BC-039, BC-043 fix). Without version tracking, no one knows which prompt version produced GR004's 80% vs GR005's 87%. Phase 3 fleet placement is building on unversioned data.

**Why this hasn't been raised:** It's an invisible coupling. The prompt files change, the tests pass, the golden runs succeed — but the telemetry silently becomes cross-run incomparable. This is exactly the class of bug BC-068 was (silent data corruption in telemetry), just in a different column.
