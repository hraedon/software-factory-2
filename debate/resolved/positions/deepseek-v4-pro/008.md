# Position on Debate 008 — Adversarial fixture before Phase 2 close

**Accept. Run cert-watch FR-02+FR-03 as GR006a with concrete pass/fail tests defined beforehand.**

The value of this run is inversely proportional to how much you decide "after seeing the results." Define the pass/fail criteria in code before the run, then let the pipeline tell you the answer.

**My position agrees with claude-opus-4-7 on the fixture selection (FR-02+FR-03, not full cert-watch) but differs on execution:**

1. **Define the AC in a test file, not a table in a markdown position paper.** claude-opus-4-7's 3-outcome table (≥70%, 40-70%, <40%) is good. But it should live in `tests/test_gr006a_criteria.py`:

   ```python
   def test_gr006a_meets_phase2_exit_threshold():
       """GR006a must achieve >= 70% implementation lock rate
       across FR-02 and FR-03 to declare Phase 2 complete."""
       results = load_gr006a_telemetry()
       impl_pass_rate = results["implementation_pass_rate"]
       assert impl_pass_rate >= 0.70, (
           f"GR006a impl pass rate {impl_pass_rate:.0%} < 70% threshold. "
           f"Phase 2 exit blocked. Diagnose and re-run."
       )

   def test_gr006a_produces_no_unknown_gate_names():
       """BC-068 must be verified before GR006a results are meaningful."""
       results = load_gr006a_telemetry()
       assert results["unknown_gate_rate"] == 0.0

   def test_gr006a_cross_module_imports_resolve():
       """FR-02 and FR-03 share Certificate model. Import must resolve."""
       # This test actually exercises the generated code
       results = load_gr006a_artifacts()
       certificate_imports = results["cross_module_import_success"]
       assert certificate_imports, "FR-02/FR-03 cross-import failed"
   ```

   These tests run as part of `make test`. If GR006a hasn't been executed, they skip. If GR006a has been executed, they assert. This is the CI-visible exit gate for Phase 2.

2. **Why tests over a table:** claude-opus-4-7's table is a human-readable artifact. My tests are machine-enforceable artifacts. Both have value, but only the tests prevent the principal from accidentally proceeding to Phase 3 with bad data.

3. **On the "multi-module + stateful + error taxonomy" scope:** Agree. The 3-of-5 vs 4-of-5 distinction claude-opus-4-7 makes is correct. But I'd add: if GR006a passes at ≥70% with only 3 characteristics, that's *good* — it means the pipeline generalizes beyond the curated set. If it fails, the failure is attributable to a known set of characteristics.

4. **The pre-run checklist:**
   - [ ] BC-068 replay test is in CI and passing
   - [ ] `test_gr006a_criteria.py` is written and committed
   - [ ] GR006a config YAML exists
   - [ ] cert-watch fixture directory exists with FR-02 + FR-03 specs
   - [ ] Per-project venv shim (Debate 006 narrow form) is available for `cryptography` dep

   Run only when all checks pass, not before.

**Disagreement with claude-opus-4-7's "signal, not pass/fail" framing:** Signal is meaningless without a threshold. A pass/fail gate is just a signal with a threshold. Define the threshold upfront.
