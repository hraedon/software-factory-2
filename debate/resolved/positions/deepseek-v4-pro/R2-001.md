# Position on R2-001 — Infinite-spend circuit breaker

**Strong accept. claude-opus-4-7's recommendation (~50 lines, coarse cost table, no rabbit hole) is correct. My only addition: write the test before the breaker.**

The budget breaker is the simplest load-bearing safety mechanism in the system. Without it, a stuck retry loop on K2 or Claude Opus burns unbounded money over a weekend. v1 had this (Global Budget Breaker). v2 needs it before Phase 3 multi-channel runs because multi-channel increases the failure-mode surface N-fold.

**What I'd add to claude's recommendation:**

1. **Write the test first.** `test_budget_exhausted_halts_pipeline()`:
   - Set `max_mission_budget = 0.01` (essentially zero)
   - Run the scheduler against a mock substrate with 10 work-items
   - Assert all items transition to `cannot_proceed` with `escalation_reason = "budget_exhausted"`
   - Assert no items transition to `locked`
   This test FAILS today. Fix it.

2. **The cost table should be a test fixture, not buried in config.** The `cost_per_token_by_provider` dict is ~6 entries. Add `test_cost_table_coverage()` that asserts every provider in `FAMILY_BY_PROVIDER` (constants.py:88) has a cost entry. When Gemini or K2 is added to the provider map without a cost entry, this test fails.

3. **`max_work_item_retries` and `max_mission_budget` are different things.** The debate conflates them under "budget." Retries are a correctness guard (prevent loops); budget is a financial guard (prevent spend). Ship both, but give them separate config keys and separate escalation reasons. "Retry budget exhausted" vs "mission budget exhausted" — different operator responses.

4. **The budget breaker should produce a telemetry event, not just a transition.** The `cannot_proceed` event's custom_fields should include `tokens_consumed`, `estimated_cost`, `budget_remaining`. The notification hook (R2-005) can read this. The post-mortem for "why did this run fail?" is in the telemetry, not in the runner log.

**Why I'm not writing a separate doc for this (per the instructions):** I agree with claude's core recommendation. The additions above are small refinements, not disagreements. Build before Phase 3.
