# Position on NEW-002 — Channel protocol cleanup

**Accept Option A: Remove `inputs_dir` from the protocol. This is a mechanical refactor that should happen before Debate 003 (dedup) and before any new adapter is written.**

## Why this is prerequisite, not independent

Debate 003 (channel adapter dedup) and BC-060 (dead parameter) are coupled. If the protocol has a dead parameter, the equivalency test (DeepSeek's Debate 003 requirement) must include the dead parameter in its contract, perpetuating the mistake. Clean the protocol first, then write the contract test.

## Why Option A over Option B

Option B (document as intentionally unused) preserves the parameter "just in case." This is the v1 pattern of accumulating dead code and justifying it with comments. Option A removes the dead parameter entirely. If Phase 5 needs artifact passing, re-add it with a real implementation and a test that proves it's used.

The cost difference is negligible: Option A is ~20 lines of mechanical refactor; Option B is ~5 lines of comment + test. But Option A prevents the parameter from becoming a footgun for 4 new adapters.

## Concrete steps

1. Remove `inputs_dir` from `Channel.invoke()` protocol.
2. Remove `inputs_dir` from `ClaudeCodeChannel.invoke()` and `OpenCodeChannel.invoke()`.
3. Remove `inputs_dir` from `runner.py:process_work_item()` invocation call.
4. Update all tests that pass `inputs_dir=Path(...)` to remove the argument.
5. Add DeepSeek's proposed `test_channel_protocol_has_no_dead_parameters` to prevent recurrence.

## Connection to Debate 003

The refactor order is:
1. NEW-002 (this item) — clean protocol
2. Debate 003 equivalency test — test clean protocol
3. Composition extraction — extract shared utilities
4. Add K2/GLM/DeepSeek/Gemini adapters — clean protocol, no dead parameters

## Blocking

Pre-Phase 3. Must happen before any new channel adapter is written.
