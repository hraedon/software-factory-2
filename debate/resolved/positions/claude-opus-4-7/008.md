# Position on Debate 008 — Adversarial fixture before Phase 2 close

**Accept and run cert-watch FR-02 + FR-03 as GR006a before declaring Phase 2 done. Defer the full cert-watch run (GR006b) to Phase 5 pre-flight.**

This is the highest-information experiment available right now. The 15 curated fixtures are deliberately small and self-contained — exactly the regime where 87–93% pass rates are *least* informative about real-world behavior. Without an adversarial datapoint, the Phase 2 → Phase 3 handoff is built on a measurement that the spec itself describes as a "vanity number" if the fixtures are unrepresentative.

**Why cert-watch FR-02+FR-03 specifically (not the full project):**

- The sf2 pipeline operates per-work-item (interface_spec → test_suite → implementation). Cert-watch as one work-item is far too large; as 5+ items, it conflates "Phase 2 pipeline fitness" with "Phase 5 workload-decomposition fitness."
- FR-02 (TLS scan + cert + chain extraction) and FR-03 (file upload + parse) share a `Certificate` model. As two linked work-items they exercise:
  - Cross-work-item module imports (`Certificate` from a third interface_spec)
  - Real I/O at gate time (sockets for FR-02, filesystem for FR-03 — needs venv + cryptography lib)
  - A non-trivial error taxonomy (bad host, refused connection, expired chain, malformed PEM, partial chain, encoding errors)
  - A genuinely stateful contract (chain extraction depends on TLS handshake state)
- We have v1 priors on cert-watch across 11 attempts, so the comparison isn't blind.

**Disagreement with the debate as written:**

Debate 008's "what an adversarial fixture includes" list (multi-module + stateful + error taxonomy + UI + AC ambiguity) is the *Phase 5 readiness fixture*, not the *Phase 2 exit fixture*. Trying to land all five characteristics in one run conflates two different questions and produces a result that's hard to interpret. Better to:

- **GR006a (this position):** multi-module + stateful + error taxonomy. Three of five. Phase 2 exit gate.
- **GR006b (later):** add UI (FR-01 dashboard) + AC ambiguity (intentionally vague AC in one FR). Phase 5 pre-flight.

The 4-of-5 / 5-of-5 fixture only makes sense after the behavioral gate (Debate 001) exists, which is itself Phase 5.

**Pass criterion:**

The debate suggests "40% as acceptable." I'd refine: GR006a's purpose is *signal*, not pass/fail. Three meaningful outcomes:

| Result | Interpretation | Action |
|---|---|---|
| ≥70% impl pass, recovery within budget | Curated fixtures *do* generalize | Phase 2 closes; proceed to Phase 3 |
| 40–70% impl pass | Generalizes partially; gap is identifiable | Close Phase 2 but file the gap as a Phase-3 monitoring item |
| <40% impl pass | Curated fixtures don't generalize | Pause Phase 3; root-cause before adding channels |

See `plans/gr006a-execution.md` for the detailed plan.
