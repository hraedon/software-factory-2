# Position on Debate 003 — `SubprocessChannel` extraction (BC-061)

**Accept the principle: refactor before any 3rd channel adapter. Caveat: keep the base conservative — don't pre-design for K2/GLM/DeepSeek/Gemini quirks you haven't met.**

Two near-identical 145-line adapters is fine; it's a known duplication, easy to refactor. Six is a ratchet. Once K2 + GLM + DeepSeek + Gemini all copy the existing pattern, every fix to artifact extraction or error formatting becomes a 6-place change and the divergence between adapters compounds. This is the v1 BC-273 god-function story rewound: it always starts as "just one more copy."

**Where I diverge from the debate as written:**

The proposed base extracts `subprocess.run`, raw_stdout capture, cannot_proceed detection, artifact extraction, error formatting, and attempt directory creation. That's defensible based on what claude-code and opencode actually share *today*, but the debate also lists hooks for K2 API (HTTP, not subprocess), Gemini CLI quirks, etc. that haven't been written yet.

Concrete recommendation:

1. **Extract only what is provably common between claude-code and opencode.** That's roughly: subprocess invocation with timeout, stdout capture and `raw_stdout.txt` write, artifact extraction via `output_extraction.py`, cannot_proceed JSON detection, the four error-formatting modes (timeout / non-zero-exit / empty-output / extraction-failure), attempt directory creation. Do NOT add abstract hooks for "auth modes" or "transport types" yet.

2. **Write the K2 adapter against this base.** K2 is the next concrete adapter. Let it teach you what *else* belongs in the base. If K2 is HTTP-not-subprocess, it might not even extend `SubprocessChannel` — it might be a sibling `HttpChannel` and the right common base is `Channel` (the existing protocol). That's *fine*. Don't force inheritance.

3. **Two refactors of clean code beat one over-engineered base.** After K2, refactor again if the base is wrong. After GLM/DeepSeek, refactor a third time if needed. Each refactor is cheap when the layer is small.

**Risk to flag:** the debate's `cli_binary() / cli_flags() / derive_family() / artifact_extension()` template-method API is reasonable but locks in subprocess as the abstraction. Make it a Protocol or ABC the subclass *can* implement, not one the base requires.

**On scope:** strict yes to BC-061 as a hard prerequisite for Phase 3; soft yes to the directory restructure (`channel/` subpackage). The directory move is cosmetic and trivial — bundle with the refactor or skip; either is fine.
