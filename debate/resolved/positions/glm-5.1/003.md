# Position on Debate 003 — Channel adapter deduplication

**Accept the principle: no third adapter until duplication is eliminated. Caveat: prefer composition over inheritance.**

Two near-identical 145-line adapters is manageable. Six is a ratchet — every fix to artifact extraction or error formatting becomes a 6-place change, and divergence between adapters compounds silently. This is the v1 "string constant gravity" pattern but with control flow.

**Where I diverge from the debate's proposed structure:**

The debate proposes a `SubprocessChannel` base class with template-method hooks (`cli_binary()`, `cli_flags()`, `derive_family()`, `artifact_extension()`). This locks in subprocess as the abstraction. K2 is API-based (HTTP), not subprocess-based. If K2 doesn't fit the base class, the base class is not the common abstraction — it's an abstraction for 2 of 6 adapters.

**Alternative: extract shared utilities, not a base class.**

```
channel/
  __init__.py
  _subprocess.py      # run_with_timeout(), capture_stdout(), format_error()
  _artifacts.py       # extract_artifacts(), detect_cannot_proceed()
  claude_code.py      # ClaudeCodeChannel — composes utilities
  opencode.py         # OpenCodeChannel — composes utilities
```

Each adapter imports shared functions and composes them. K2 adapter imports what it needs (artifact extraction, cannot_proceed detection) and skips subprocess-specific helpers. No inheritance hierarchy, no template methods, no commitment to a single abstraction.

**Advantages over inheritance:**

1. K2 can reuse artifact extraction without pretending to be a subprocess.
2. A future adapter with exotic error handling can skip `format_error()` and write its own without overriding.
3. No risk of the base class becoming a god-class as more adapters accumulate.
4. Each utility function is independently testable.

**Concrete recommendation:**

1. Extract `run_with_timeout()`, `capture_stdout()`, `format_invoke_error()`, `extract_artifacts_from_output()`, `detect_cannot_proceed()` as standalone functions in `_subprocess.py` and `_artifacts.py`.
2. Refactor `ClaudeCodeChannel` and `OpenCodeChannel` to thin wrappers that compose these functions.
3. Write K2 adapter against the shared utilities. If K2 needs subprocess helpers, great — it composes them. If it needs HTTP helpers, it uses something else entirely.
4. Move BC-061 to `in_progress`, resolve in 1 session.

**On scope:** Yes to BC-061 as a hard prerequisite for Phase 3. The directory restructure (`channel/` subpackage) is cosmetic — bundle with the refactor.
