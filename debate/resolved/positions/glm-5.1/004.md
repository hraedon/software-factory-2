# Position on Debate 004 — Pipeline checkpoints

**Defer. Regista state is already the checkpoint.**

The debate proposes a checkpoint JSON file that snapshots stage-level progress. But regista already stores exactly this information: work-item states, transitions, claims, and events. On runner restart, querying `sub.query_work_items(state="locked")` per work-item-type tells you which stages are complete. The existing BC-003 idempotency (scan prior attempts for valid manifests) handles per-item resume. The checkpoint file is a redundant, staleable copy of what regista already knows.

**What the debate gets right:**

The `--continue` and `--retry-escalated` CLI modes are valuable. But they don't need a checkpoint file — they need the runner to query regista on startup and decide what to do:

- `--continue`: Query all work-items. Skip locked items. Resume in-progress items via BC-003 manifest scan. Claim new items as normal.
- `--retry-escalated`: Query work-items in `cannot_proceed` state. Reset them to `new` via a new transition. Claim and process normally.

Both modes are implementable with existing regista queries and ~50 lines of runner code. No new files, no new JSON schema, no symlink management, no config hash validation.

**Why the debate's proposal is over-scoped:**

The checkpoint JSON includes `config_hash`, `timestamp`, and per-stage UUID lists. This creates a new consistency problem: what if the checkpoint says 12/15 items are locked but regista says 10? Which is authoritative? Regista must be authoritative (it's the event-sourced truth). If regista is authoritative, the checkpoint file is advisory at best and misleading at worst.

**When this becomes real:** Phase 3 multi-channel runs with fallback chains could push wall-clock to hours. At that point, the `--continue` mode becomes load-bearing. But the implementation path is still "query regista on startup," not "read checkpoint file." The checkpoint adds complexity without adding information.

**Minimum viable improvement:** Add `--continue` flag to runner that queries regista for current state and resumes from there. One session, no new modules, no new files.
