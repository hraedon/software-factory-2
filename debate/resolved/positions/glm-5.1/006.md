# Position on Debate 006 — Per-project venv isolation

**Accept, narrow to a 50-line helper function. Defer to pre-Phase 5.**

The problem is real: generated code declaring `import pydantic` fails the pytest gate because pydantic isn't in the factory venv. The fix is correct: run gates in a per-project venv with the generated code's dependencies. But the debate's 6-step "next steps" list and proposed `VenvManager` class over-scope something that should be a simple utility.

**Proposed implementation (~50 lines):**

```python
def ensure_project_venv(project_dir: Path, config: FactoryConfig) -> Path:
    venv_dir = project_dir / ".venv"
    req_file = project_dir / "requirements.txt"
    marker = venv_dir / ".deps_hash"
    current_hash = hashlib.sha256(req_file.read_bytes()).hexdigest() if req_file.exists() else ""
    if venv_dir.exists() and marker.exists() and marker.read_text() == current_hash:
        return venv_dir / "bin" / "python"
    if venv_dir.exists():
        shutil.rmtree(venv_dir)
    subprocess.run([sys.executable, "-m", "venv", str(venv_dir)], check=True)
    pip = venv_dir / "bin" / "pip"
    subprocess.run([str(pip), "install", "pytest", "mypy", "ruff"], check=True)
    if req_file.exists():
        subprocess.run([str(pip), "install", "-r", str(req_file)], check=True)
    marker.write_text(current_hash)
    return venv_dir / "bin" / "python"
```

No class. No `VenvManager`. No dependency parser for `pyproject.toml`. Cache by `requirements.txt` hash. If no requirements file, create an empty venv with just the tools. If the hash changes, recreate.

**Why not the debate's design:**

- `VenvManager` class: state management for what is fundamentally a one-shot operation. The venv either exists with the right deps or it doesn't.
- `pyproject.toml` dependency parsing: Phase 5 generated code may not have a pyproject.toml. `requirements.txt` is the universal Python convention. If a generated project uses pyproject.toml, the implementer should also produce a requirements.txt (or the factory generates one from pyproject.toml as a pre-gate step).
- Config flag `use_project_venv: bool`: reasonable but not needed until Phase 5. Default off is correct.

**Timing:** Pre-Phase 5, not before. Phase 2/3/4 curated fixtures have no external dependencies. Building venv isolation before it's needed is infrastructure without a consumer.
