# Position on Debate 009 — Event schema evolution

**Accept the consumer-level schema pilot. Defer the regista-level registry.**

BC-068 is the case study: producer (`gate_process.py`) and consumer (`telemetry.py`) changed event payload shapes independently, with no versioning, no schema check, and no failure when shapes diverged — only silent data degradation. The fix is schema discipline between producer and consumer. The question is where to enforce it.

**Why consumer-level is right for now:**

Regista has one active consumer (v2 factory). A regista-level schema registry serves one client. The registry itself would be significant regista engineering (new API surface, version negotiation, migration for existing events, validation modes) for a benefit that can be achieved with a single file in the consumer:

```python
# factory/event_schemas.py
@dataclass(frozen=True)
class GatePassPayload:
    gate_name: str
    passed: bool
    diagnostics: list[str]

@dataclass(frozen=True)
class SubmitPayload:
    role: str
    channel: str
    family: str
    attempt_number: int
```

Both `gate_process.py` (producer) and `telemetry.py` (consumer) use these dataclasses. A round-trip test: construct → serialize → deserialize → assert equal. Cost: ~1 hour. Benefit: every future event-shape change is caught at CI time, not golden-run time.

**When to push into regista:**

When a second consumer appears (audit tool, principal dashboard, another project), the consumer-level schema becomes N copies. At that point, the schema belongs at the spine. But building the registry before the second consumer exists is infrastructure without a user. The consumer-level pilot produces the schema definitions that will eventually migrate into regista — no wasted work.

**On the debate's "soft validation: warn, don't reject":**

Correct. Regista's append-only guarantee means it must never reject an event for payload shape. Logging a warning and setting a `payload_schema_warning` flag is the right behavior. But this is a regista feature, not a consumer feature. For now, the consumer validates its own inputs and logs mismatches. If the warning rate exceeds a threshold, that's the signal to push into regista.
