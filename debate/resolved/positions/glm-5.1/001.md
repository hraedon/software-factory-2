# Position on Debate 001 — Behavioral / Playwright gate

**Defer implementation to Phase 5. Write a spec subsection and a no-op stub now.**

The debate correctly identifies the gap: mechanical gates catch structural correctness, not semantic correctness. Luke's validation data (60% wall-clock, never succeeds first pass) is strong external evidence. But building Playwright infrastructure before any fixture has a UI is textbook YAGNI. Phase 2/3/4 fixtures are libraries — functions, ADTs, error taxonomies. Running Playwright against artifacts with no entrypoint produces zero signal and adds browser binaries + flake surface to every gate run.

**What to do now (1 hour):**

1. Add `spec.md` §6 subsection: behavioral gate ordering (after mechanical, before frontier judge), failure routing (back to implementer with screenshots/DOM state), AC↔scenario binding contract.
2. Add `behavioral_gate.py` stub that returns `GateResult(passed=True, skipped=True)` unless `behavioral_scenarios` is present in work-item custom_fields.
3. Add `behavioral_scenarios: []` to the work-item schema (no consumer yet).

**What not to do now:**

- Do not generalize to "computer use" via `behavioral_spec` YAML. Two interaction modes do not exist. Premature abstraction is the v1 pattern.
- Do not install Playwright. The dependency cost (browser binaries, CI complexity, flake potential) is not justified until there's a UI target.
- Do not wire the stub into `evaluate_implementation()` yet. A gate that never fires is dead code that rots between uses (v1 precedent).

**Phase 5 trigger:** The cert-watch FR-01 (dashboard) is the natural pilot. Cert-watch has forms, navigation, and data display — exactly the LoB UI pattern the gate targets.

**One area where the debate underestimates the opportunity:** the behavioral gate isn't just for UI. Even in Phase 3/4, a CLI-level behavioral check (run the produced module, verify output against expected) would catch a class of "passes tests but doesn't actually work" failures. But this is already partially covered by the mechanical gates (pytest runs the code). The marginal value over pytest is small until the artifact is a standalone application, not a library.
