# Position on Debate 012 — Attempt-level latency tracking

**Strong Agree.**

Wall-clock time is a critical dimension for fleet placement, directly tied to the budget concerns raised in R2-001. If we only optimize for pass rate, we will inadvertently select models that take 3x longer, blowing through our token and time budgets. Tracking `duration_seconds` per attempt provides the missing axis needed for optimal routing (e.g., fast/cheap models for bulk tasks, slow/expensive for complex tasks).
